# План работы: arXiv semantic search + RAG

Команда: 2 человека. Партнёр не пишет код — распределяем так, чтобы его вклад был весомым, но не требовал программирования.

## Шаг 0 — Организационное (1 день)

- Написать преподавателю про команду из 2 человек (бриф: "если класс не делится ровно на 3 — обсудить с преподавателем"). Сделать это первым, до старта работы.
- Завести общий репозиторий (GitHub) и канал для связи.
- Зафиксировать финальный scope: категории math.PR, math.ST, math.CO, math.OC, период — последние 3 года, решить, включаем ли Kafka или упрощаем до Spark + Elasticsearch.

## Шаг 1 — Данные (партнёр ведёт, ты помогаешь с инструментами)

- Ты: скачиваешь и фильтруешь arXiv metadata по категории/дате, кладёшь партнёру в удобный формат (CSV/Excel-выгрузка или Jupyter-таблица, которую можно скроллить без кода).
- Партнёр: вручную просматривает выборку, проверяет качество (пустые абстракты, дубли, странные категории), решает, какие KPI и инсайты интересны для презентации ("какие темы растут", "какие категории самые активные" и т.п.). Это не требует кода — просто анализ данных глазами и формулирование вопросов.

## Шаг 2 — Пайплайн (ты, код)

- (опционально) Kafka: топик + продюсер, публикующий статьи как события.
- Spark: чистка текста, фильтрация, подсчёт KPI, которые определил партнёр на шаге 1.
- Elasticsearch: индекс со схемой (метаданные + поле под вектор).

## Шаг 3 — AI-компонент (ты, код)

- Эмбеддинги на sentence-transformers (локально, без API) для абстрактов, запись в Elasticsearch `dense_vector`.
- Семантический поиск: функция "запрос → топ-k статей".
- RAG: запрос пользователя → поиск релевантных абстрактов → LLM формирует ответ с ссылками на статьи.

## Шаг 4 — Проверка качества (партнёр ведёт)

- Партнёр прогоняет десятки тестовых вопросов через поиск и RAG, отмечает: находит ли релевантные статьи, не выдумывает ли LLM факты, какие запросы ломаются. Это ключевая некодовая роль — валидация результата глазами человека, разбирающегося в теме.
- Ты по фидбэку партнёра донастраиваешь промпты/фильтры.

## Шаг 5 — Документы и презентация (партнёр ведёт, ты вычитываешь техническую часть)

- Дизайн-документ на 1-2 страницы: архитектура, data flow, технологии, AI-компонент.
- README с инструкцией запуска.
- Слайды и сценарий демо (5-10 минут) + подготовка к вопросам.

## Шаг 6 — Понимание вместе (важно для оценки)

- Grading явно даёт вес "Understanding and Q&A" — важно, чтобы партнёр мог объяснить логику проекта своими словами, даже не написав код. Стоит сделать 2-3 коротких созвона, где ты проговариваешь партнёру, что делает каждый блок (зачем эмбеддинги, что такое RAG, зачем Elasticsearch), а не просто присылаешь готовое.
- Финальная репетиция вдвоём: партнёр должен уметь ответить на "а что если мы уберём этот шаг" и "почему выбрали Elasticsearch, а не обычную БД".
